This week

Last week, you explored an elevation raster. This week, you will combine it with weather stations and municipality boundaries. Our guiding question is:

What can an elevation model tell us about weather stations and municipalities, and how could we use it to estimate temperature?

By the end of this session, you should be able to:

  • turn a table of coordinates and measurements into a spatial point dataset;
  • inspect vector attributes and select features by attributes or location;
  • explain the difference between assigning a coordinate reference system (CRS), transforming coordinates and cropping data;
  • extract raster values for points and polygons, and explain what the resulting numbers represent.

The homework connects these skills with a simple linear model. The loop exercise is an optional extension.

Start in QGIS: explore the three datasets

Spend about 15–20 minutes getting to know the data before processing them in R. The steps below also work if you are new to QGIS. Menu names are given in English.

A. Open QGIS and add the map layers

  1. Start QGIS and choose Project → New. The central area displays your map; the Layers panel lists its datasets. If this panel is missing, enable it under View → Panels → Layers.
  2. Drag n48_e008_1arc_v3.tif from your file manager into the map area. This is the digital elevation model (DEM): each raster cell stores an elevation value.
  3. Drag AX_KommunalesGebiet.shp into the map area. Add the .shp file only, but keep its accompanying files in the same folder. Each polygon represents a municipality area.
  4. Right-click the DEM in the Layers panel and choose Zoom to Layer. Use the mouse wheel to zoom; select the Pan Map tool (hand icon) and drag to move around.

B. Make the elevation raster visible beneath the boundaries

  1. In the Layers panel, drag the municipality layer above the DEM. Layers higher in the list are drawn on top.
  2. Right-click the municipality layer and choose Properties → Symbology. With Single Symbol selected, click the symbol preview, then select Simple Fill in the symbol layer tree.
  3. Set Fill style to No brush and retain a visible stroke colour and solid stroke. Click OK to close the dialogs. You should now see municipality outlines over the DEM.

C. Add the weather stations from the CSV

  1. Choose Layer → Add Layer → Add Delimited Text Layer. Browse to stations_bawue_montly_temp.csv.
  2. Under File format, choose Custom delimiters, select Semicolon and clear the other delimiters. Enable First record has field names, Detect field types and Decimal separator is comma. Check that the preview separates the fields correctly.
  3. Under Geometry definition, choose Point coordinates and set X field = Lon, Y field = Lat. For Geometry CRS, select EPSG:4326 – WGS 84, using the CRS selector to search for 4326 if needed. This is the longitude/latitude CRS used for the station coordinates in this exercise.
  4. Click Add, then Close. Drag the station layer to the top of the Layers panel. If the points are difficult to see, open its Properties → Symbology and choose a contrasting colour, such as red.

D. Explore the information behind the map

Right-click the station layer and select Open Attribute Table. Each row describes a station; the columns contain its attributes. Find Station, Lon, Lat and the temperature fields. Close the table, then open the municipality layer’s attribute table and locate the name field NAME.

E. Check the coordinate reference systems

A coordinate reference system (CRS) defines how coordinate values relate to locations on Earth. Geographic CRSs use longitude and latitude in degrees; projected CRSs use coordinates on a flat map, often in metres.

For an introduction, see QGIS: Coordinate Reference Systems.

For each of the three layers, right-click its name and open Properties → Information. Find the CRS and note its name and coordinate units. An EPSG code, where shown, identifies a particular CRS. Record each layer’s CRS; the project CRS shown at the bottom of the QGIS window describes the map display.

Save your project with Project → Save As, for example as week3_exploration.qgz in your course folder.

Observe and explain:

  • Does the DEM cover all stations and all municipalities?
  • Are the stations spread evenly across the area and across low and high terrain?
  • Which information belongs to an individual station, and which belongs to a municipality?
  • If the layers align on screen, does that prove that their stored coordinates use the same CRS?

Keep these observations: you will check them in R.

2.3 Create a point layer

Use vect() to turn the table into a SpatVector. In geom, provide the coordinate columns in x, y order: longitude first, latitude second.

First check whether any coordinate pairs are missing. Rows without a complete pair cannot provide point locations; report their number and omit them from the point layer. Do not remove a station merely because a temperature measurement is missing.

Show code
valid_xy <- complete.cases(temp[, c("Lon", "Lat")])
sum(!valid_xy)

temp.point <- vect(temp[valid_xy, ],
                   geom = c("Lon", "Lat"),
                   crs = "EPSG:4326")

temp.point
class(temp.point)
head(values(temp.point))
head(crds(temp.point))

The CRS describes what the existing coordinates mean. Here, EPSG:4326 follows the WGS 84 assumption in the course exercise. For another dataset, check its source metadata before assigning a CRS.

Change and explain: What would go wrong if you reversed Lon and Lat? Would assigning a different CRS label correct that mistake?

4. Match coordinate systems and spatial extents

4.1 Diagnose before transforming

Predict whether the original layers can be combined directly with plot(..., add = TRUE). Inspect their coordinate systems and extents first.

Show code
crs(DEM, describe = TRUE)
crs(temp.point, describe = TRUE)
crs(poly, describe = TRUE)

ext(DEM)
ext(temp.point)
ext(poly)

Compare CRS names or identifiers and coordinate units. Large differences in coordinate magnitudes can be a clue, but do not identify a CRS on their own.

QGIS can transform layers for display without changing their stored coordinates. For the R overlays below, explicitly bring the vector layers into the DEM’s CRS before plotting them together.

4.2 Transform the vector layers

Use terra::project() and the DEM’s CRS as the target. The original objects remain available for comparison. If the points already use the target CRS, their positions should remain unchanged.

Show code
temp.dem <- terra::project(temp.point, crs(DEM))
poly.dem <- terra::project(poly, crs(DEM))

crs(temp.dem, describe = TRUE)
crs(poly.dem, describe = TRUE)

plot(DEM, col = terrain.colors(25), main = "DEM, municipalities and stations")
plot(poly.dem, add = TRUE, col = NA, border = "grey30")
plot(temp.dem, add = TRUE, pch = 19, cex = 0.7, col = "red")
ImportantAssigning a CRS is not transforming coordinates

crs(poly) <- crs(DEM) would replace the CRS description while leaving the coordinate numbers unchanged. It is not a way to transform the polygons. project() calculates coordinates in the target CRS using the known source CRS.

Here we transform the vectors to the DEM’s CRS. Reprojecting the raster would require estimating values on a new grid.

Explain: Why are the polygons drawn without a fill, and why are the stations plotted last?

4.3 Crop to the DEM extent

The layers now use a common CRS, but they may still cover different areas. Crop the polygons and points to the DEM’s rectangular extent.

Show code
poly.clip <- crop(poly.dem, ext(DEM))
temp.clip <- crop(temp.dem, ext(DEM))

nrow(poly.dem)
nrow(poly.clip)
nrow(temp.dem)
nrow(temp.clip)

plot(DEM, col = terrain.colors(25), main = "Layers within the DEM extent")
plot(poly.clip, add = TRUE, col = NA, border = "grey30")
plot(temp.clip, add = TRUE, pch = 19, cex = 0.7, col = "red")

Inspect the edges: Which municipalities have been cut by the boundary of the DEM? Does crop() keep their original boundaries? Does being inside the raster’s extent guarantee that a location has a non-missing elevation value?

NoteWhat area will your statistics describe?

For a municipality that crosses the DEM boundary, a mean computed from poly.clip describes only its part inside the DEM, using the available elevation cells. It is not necessarily the mean of the whole municipality.

5.3 Calculate and attach mean elevations

Use fun = mean to obtain one summary value per polygon. Use na.rm = TRUE to omit missing raster values from each mean.

Show code
DEM.poly.mean <- extract(DEM, poly.stations,
                         fun = mean, na.rm = TRUE)

head(DEM.poly.mean)
nrow(DEM.poly.mean)

The ID column returned here refers to the row number in the vector object passed to extract(), not to an official municipality identifier. Keep the polygon order unchanged and check the correspondence before attaching the result.

Show code
stopifnot(nrow(DEM.poly.mean) == nrow(poly.stations))
stopifnot(all(DEM.poly.mean$ID == seq_len(nrow(poly.stations))))

poly.stations$mean_elev_m <- DEM.poly.mean$elevation_m
head(values(poly.stations))
summary(poly.stations$mean_elev_m)

Explain: What would happen without na.rm = TRUE if a polygon included missing DEM values? If it had no valid values at all, would removing missing values create a meaningful mean?

These are means of the extracted cell values. They are not exact area-weighted estimates: cell inclusion at polygon boundaries and varying cell areas in a longitude/latitude grid can affect the result.

Homework: elevation and January temperature

Question: How can we use the relationship between elevation and January temperature to create a temperature map?

The station data used in this exercise show a strong relationship between elevation and January temperature. You will quantify this relationship with a linear regression and apply the fitted model to the DEM.

Use the temperature column temp_2016_1. Save your commands in a commented R script that produces a scatterplot with a regression line and a temperature map. Include brief answers as comments in your script and refer to your own results. No separate written report is needed.

A. Build a station-level analysis table

  1. Extract the DEM value at each station in temp.dem, the full point layer in the DEM’s CRS. Use extract() with its default point method, which returns the value of the cell containing the station.
  2. Inspect the returned table. Distinguish its ID column from the actual Station identifier. Combine the extracted elevation_m values with attributes from values(temp.dem), keeping each station’s elevation and temperature together.
  3. Keep station identifier, DEM elevation and January temperature in one analysis table. Check that elevation and temperature are numeric, and identify any missing values.
  4. Select the complete elevation–temperature pairs with complete.cases(). Use the same pairs for the scatterplot, correlation and regression. Report how many stations are included.

Useful functions: extract(), values(), data.frame(), str(), lm(), abline(),is.na(), complete.cases() and sum().

Hint: Stations outside the DEM have no extracted elevation. A location inside the DEM can also have a missing raster value. Remove incomplete rows from the combined table so that elevation and temperature remain paired correctly.

B. Explore and fit the relationship

Before calculating anything, predict the direction of the relationship. Then:

  1. Make a scatterplot with elevation on the x-axis and January temperature on the y-axis. Label both axes with their units.
  2. Calculate Pearson’s correlation coefficient, \(r\). Explain what use = "complete.obs" does in cor(). If you have already selected complete pairs, should it change the result?
  3. Fit a linear model with lm(). Use temperature as the response and elevation as the predictor. Inspect summary() and coef() of your fitted model and add its regression line to the scatterplot with abline().
  4. Report the number of stations used, the intercept, the slope, \(r\) and the model’s \(R^2\).
  5. Interpret the slope as a temperature difference per 100 m of elevation. What temperature does the fitted equation predict at an elevation of 0 m, and which coefficient represents this value?

Use this model form:

\[ \widehat{T}_{\mathrm{Jan}} = a + b\,z, \]

where \(z\) is elevation in metres, \(a\) is the intercept and \(b\) is the slope. For a simple ordinary least-squares model with an intercept, fitted to the same complete pairs, \(R^2 = r^2\).

C. Apply the model to the DEM

Use the fitted intercept and slope to calculate a temperature estimate for every DEM cell with a valid elevation. Apply the equation above through raster algebra. You can obtain the coefficients with coef(); check their names before using them.

As a reminder, raster algebra operates on cell values. For example, converting elevations from metres to centimetres would require multiplying by 100.

Map the result with an informative title, a temperature legend in °C and the station locations. Save the raster as a GeoTIFF in your output folder using writeRaster().

Check the result:

  • How do the sign and magnitude of the fitted slope determine the map’s spatial pattern?
  • Choose one relatively high and one relatively low location. Use the fitted equation to explain the difference between their estimated temperatures.
  • Compare the map with your station scatterplot. Does the mapped pattern agree with the relationship you fitted?

D. Interpret and check your results

Add brief answers as comments in your script:

  • What does your \(R^2\) tell you about how well the linear model explains the differences in January temperature between the stations?
  • How much does the predicted temperature change for a 100 m increase in elevation? Refer to your fitted slope.
  • Why do we use the DEM elevation at each station to fit the model, rather than the mean elevation of its municipality?

The map shows temperature estimated from elevation using the relationship fitted to the weather stations for January 2016.

Check your work: Run your script from the beginning in a fresh R session. Check that it reproduces both figures and that your comments refer to your own sample size, coefficients and \(R^2\). Bring your script and results to the next seminar and be prepared to explain how the fitted equation is applied to the raster. Follow the course instructions for submission.

Optional extension: repeat an operation with a loop

The direct call extract(DEM, poly.clip, fun = mean, na.rm = TRUE) can calculate means for multiple polygons. A loop is useful here as a programming exercise; do not assume it is automatically faster or more memory-efficient.

Understand a small example

Before running this code, predict the contents of squared after the first two iterations. Explain which value changes in each iteration and where the result is stored.

Show code
input <- seq(1, 20, by = 2)
squared <- numeric(length(input))

for (i in seq_along(input)) {
  squared[i] <- input[i]^2
}

squared

Change the example so that it calculates cubes instead of squares. What does seq_along(input) return?

Transfer the idea to polygons

Use poly.clip, so that the polygons are already in the DEM’s CRS and clipped to its extent.

  1. Start with the first ten features, or all features if there are fewer than ten. Record their order.
  2. Prepare a numeric result vector of the required length, initially filled with NA_real_. Useful syntax: rep(NA_real_, nrow(your_polygons)).
  3. Loop over seq_len(nrow(your_polygons)). Extract the mean elevation for polygon i, allowing for missing DEM values, and store the elevation value, not the extraction ID, in position i.
  4. Compare your result with a single extract(..., fun = mean, na.rm = TRUE) call on the same polygons. Explain any differences before extending the loop to all features in poly.clip.
  5. Attach the result to the polygon layer in the same row order and make a map. Remember that boundary polygons are incomplete municipality areas.

Reflect: Which approach is easier to read for this task? Can you think of a situation in which different operations for each polygon would make a loop useful?
